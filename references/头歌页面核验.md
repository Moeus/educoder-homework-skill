# 头歌实训页面核验与做题流程

核验日期：2026-11-24。课堂：[Java Web 程序设计实训作业](https://www.educoder.net/classrooms/WZPF4KHQ/shixun_homework)。以下页面观察来自已登录的头歌关卡；接口相关内容引用本项目的既有记录。本文只针对**实训关卡**，不把结论推广到独立编程作业或考试。

## 核心规则

每进入一个小题，点击右侧「代码文件」文字旁的 `.ant-dropdown-trigger`，把菜单中**全部路径**记为这一关要编辑的文件。菜单可能是一项，也可能是多项。切到下一关后重新打开菜单，不能沿用上一关的列表。右侧「显示目录」给出可阅读的工程文件；目录中的其他文件可以用于理解依赖和测试，但本次操作按用户明确给出的规则，只编辑当前小题菜单列出的文件。

用户提供的控件示例为 `#env_1589872_1 .ant-dropdown-trigger`。本轮 JavaBean 三关在这一控件中逐项看到了下表路径。`env_...` 的数字随作业变化，不能把示例 ID 写死为所有题目的选择器。

既有[接口实测记录](./接口实测记录.md)对公开前端组件的核对称：在适用的关卡分支中，菜单来自 `challenge.path.split('；').filter(Boolean)`，首项默认打开；分隔符是**全角分号**。本轮核对的是页面菜单，没有重新抓取各关 `challenge.path` 或验证此实现覆盖所有题型。实现 skill 时以实际页面菜单为准，接口字段可作为辅助核对。[头歌 API 草案](./头歌api.md)中的示例响应不等于本轮实测响应。

## MVC 作业：完整操作实例

本轮完成了[基于 MVC 模式的用户登录](https://www.educoder.net/classrooms/WZPF4KHQ/shixun_homework)两关。操作与评测结果如下，供后续 skill 参考。

1. **进入关卡并确认文件。** 第一关菜单只有 `chapter9/WebContent/login.jsp`。题面要求表单字段 `userName`、`password`，提交到 `login`。在该 JSP 写入登录表单，点击「评测」后看到 `1 / 1 全部通过` 和通关提示，再进入下一关。
2. **重新读取第二关菜单。** 它只列 `chapter9/src/chapter9/LoginServlet.java`。题面要求 `doGet` 用 JDBC 查询 `university.student`，把用户封装成 `StudentBean`，存入 session 属性 `account`，根据结果到 `success.jsp` 或 `fail.jsp`。
3. **阅读相关工程文件。** 「显示目录」中读取 `StudentBean.java`，确认字段及 setter；读取 `success.jsp` 和 `fail.jsp`，发现两页都从 session 的 `account` 取值；读取 `src/test/Tep1Test2.java`，发现测试直接调用 Servlet 的 `doGet`，再取响应的 `Location` 头渲染对应 JSP。因此这里应使用 `sendRedirect`，仅按题面想当然地 `forward` 无法满足该测试。`src/test/InitDB.java` 还给出了测试库的表结构和样例数据。这些文件只读，实际编辑仍限于菜单中的 Servlet。
4. **实现并首次评测。** Servlet 用参数化 SQL 查询用户名和密码，成功时填充 `StudentBean`、存入 `account` 并重定向 `success.jsp`；失败时重定向 `fail.jsp`。首次结果为 `1 / 2`。
5. **读失败反馈并定位原因。** 展开失败的「测试集1」：输入 `李四 751254`，预期是失败页中显示这组输入；实际为 `fail.jsp` 的 `NullPointerException`。另一组成功登录的预期与实际一致。结合失败页源码，发现失败路径没有给 session 设置 `account`。
6. **修正并重测。** 在查询前用输入的用户名和密码创建 `StudentBean` 并存入 session；成功时再填充数据库返回的其余字段。重新评测显示 `2 / 2 全部通过` 和通关提示。最终作业两关均通过。

这次反馈说明：先看**汇总通过数**；再打开具体失败测试集，逐项核对**测试输入、预期输出、实际输出/异常栈**；把异常与题面和相关源码对应；只修改菜单指定文件；重新评测至全部通过。`评测` 点击后会经历服务启动和执行阶段，不能把启动提示当最终结果。最终应看本次的新通过数及作业关卡状态，不要只凭点击成功判断完成。

## 建议写进 skill 的关卡循环

1. 从课堂作业列表或详情进入实战，记录作业名、关卡名、当前进度和 URL。作业详情的通过状态用于判断已有完成关卡；进入实战后再以当前关卡页面为准。
2. 阅读「任务描述」「编程要求」「测试说明」，查看题面图片与现有代码。每关点击「代码文件」下拉菜单，记录完整路径、顺序和数量。若是预览界面，切到「代码」。
3. 若有「显示目录」，按需只读相关工程文件，优先查看被调用的类、结果页、配置与 `test` 文件。测试源码可以暴露实际调用方式、断言或输出格式；题面和测试应一起理解。若没有目录，就依据题面、菜单文件和编辑器当前内容完成填写。
4. 只在当前关菜单中的文件编辑。多文件题逐项切换、保存并核对内容；切关后重新获取菜单。工程目录中出现其他文件，不等于该关要求修改它们。
5. 点击「评测」，等待本次最终结果。若未全过，展开失败测试集，读取输入、预期、实际、编译错误或异常栈，定位差异后修正，并再次评测。保留通过用例的行为。
6. 确认每关显示全部通过，再进入下一关。完成最后一关后核对作业总进度。
