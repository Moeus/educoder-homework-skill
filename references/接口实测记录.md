# 头歌接口摸排与实测记录

日期：2026-11-23。环境：用户已登录的 Microsoft Edge，`www.educoder.net`。本记录不保存 Cookie、签名密钥、密码或个人题目代码。

## 证据分级

- **浏览器页面实测**：通过 Edge 打开页面，观察 URL、页面内容和导航结果。
- **浏览器网络面板可见**：看到请求名、状态码；对一条关卡详情请求核对了方法、部分请求头名称和响应字段。未将完整请求头、请求体和响应体导出。
- **直接 HTTP 实测**：在同一 Edge 中直接访问 JSON URL，读取返回 JSON；没有构造文档所述签名请求头。
- **仅文档描述**：`头歌api.md` 给出的约定，目前尚未在本次环境中逐接口验证。

不能把页面可访问等同于底层 JSON 接口已验证，也不能把文档中的示例响应当成真实响应。

## JSON 接口验证结果

| `头歌api.md` 中的接口组 | 本次结论 |
| --- | --- |
| 登录 `POST /api/accounts/login.json` | 未发送登录请求。Edge 已有登录态，不能由此验证密码请求格式、返回 Cookie 或 `zzud`。 |
| 课程 `GET /api/courses.json` | 无签名头直接访问 `https://data.educoder.net/api/courses.json?page=1&limit=1&order=mine&search=`，返回 `{"status":-102,"message":"服务器时间与您的设备时间不匹配，请检查您的设备时间设置并重新加载页面。"}`。因此该方法不能验证课程响应结构；`-102` 也不能单独证明本机时钟有误，缺少时间戳或签名可能触发同类错误。 |
| 实训关卡详情 `GET /api/tasks/{task_id}.json` | DevTools 中确认 `GET /api/tasks/{task_id}.json?homework_common_id={id}&zzud={login}` 返回 HTTP 200。响应正文可见 `challenge.id`、`challenge.subject`、`challenge.task_pass`、`challenge.path`、`challenge.position` 等字段；请求头列表含 `Pc-Authorization`、`X-Edu-Signature`、`X-Edu-Timestamp`、`X-Edu-Type`。敏感值未记录。此请求的发起程序显示为现有复制辅助脚本，故不能由此推断原站前端必定以相同方式调用。 |
| 作业列表、个人题目、WebSSH | 已通过页面验证对应业务流程或界面入口，但**没有**逐个完成文档所述 JSON 方法、参数、响应字段的端到端实测。 |
| `rep_content.json` | 指定 JavaWeb 作业中，`GET /api/tasks/{task_id}/rep_content.json?path={编码后的仓库相对路径}&homework_common_id={id}&exercise_id=&zzud={login}` 随点击文件发出。响应的 `content.content` 为 Base64，另含 `filename`、`language`、`size`、`file_type`；未见可写标志。 |

文档中的 `X-EDU-Signature` 算法、`AK/SK` 来源、`Pc-Authorization` 与 Cookie 关系，以及各接口业务 `status` 语义，仍需在真实请求中验证。直接访问 API 的 `-102` 表明自动化客户端必须先解决请求约定，不能把文档示例直接当作可运行 SDK。

### 本次新增的请求名

以下请求在实训关卡加载期间出现在 Network 面板，属于进一步调查线索；除上表关卡详情外，未核对方法和业务响应。路径中的标识均已泛化：

| 观察到的路径 | HTTP 状态 | 备注 |
| --- | --- | --- |
| `/api/setting.json` | 304 | 页面配置请求。 |
| `/api/users/get_user_info.json?course_id=...&school=1&coursesId=...&game_id=...` | 304 | 用户与课程上下文。 |
| `/api/tasks/{task_id}/cost_time.json?time=...` | 网络面板可见 | 关卡用时同步；读取页面可能产生计时写入。 |
| `/api/myshixuns/{numeric_id}/version_repository_delete.json` | 304 | 名称含 `delete`，但本次未核对方法和副作用；禁止依据名称调用。 |
| `/api/myshixuns/{identifier}/session_report.json` | 200 | 多次出现，发起程序为复制辅助脚本；是否属于头歌原站流程待确认。 |

Edge 中安装了“头歌复制助手”用户脚本。Network 的“发起程序”列多次指向该脚本，所以以上新增请求不能直接归因为头歌原站页面；下一轮应使用无扩展的专用配置文件复核。

## 指定 JavaWeb 多文件作业实测

入口为 [（必做）JavaBean应用第三关](https://www.educoder.net/tasks/WZPF4KHQ/4029722/arucwj38yk9e)，作业 ID 为 `4029722`。项目根目录 `JavaWeb`，含 `WebContent`、`src/com.wgh.com`、`src/test`、`resource`、`build`、`build.xml` 等。测试源码可读取，用于理解题意；不能因此推断它属于应提交的解答文件。

| 操作 | 已观察到的接口契约 | 结论 |
| --- | --- | --- |
| 列根目录 | `POST /api/myshixuns/{myshixun_identifier}/repository.json?zzud={login}`，请求体 `{}`，HTTP 200 | 响应 `trees[]`，每项有 `name`、`path`、`type`；根目录返回 `JavaWeb`。 |
| 列子目录 | 同一接口，请求体 `{"path":"JavaWeb"}`，HTTP 200 | `type=tree` 是目录，`type=blob` 是文件。必须递归列目录才能得到完整文件树；该接口不是一次下载整个工程。 |
| 读文件 | `GET /api/tasks/{task_id}/rep_content.json`，查询含 `path`、`homework_common_id`、`exercise_id`、`zzud` | 以 `path` 逐个读取 `blob`；文件正文在 `content.content` 中以 Base64 编码。 |
| 保存文件 | `POST /api/myshixuns/{myshixun_identifier}/update_file.json?zzud={login}`，HTTP 200 | 实测请求体含 `path`、原文 `content`、`evaluate:0`、`game_id`、`homework_common_id`、`tab_type:1`、`exercise_id:null`、`extras`。响应含 `content.commitID`、`content.content`、`content.size`、`resubmit`、`sec_key`。敏感值不记录。 |

完整工程读取算法：以 `{}` 列根 → 对每个 `tree` 用其 `path` 递归列目录 → 对每个 `blob` 用 `rep_content.json` 读取并解码。需限制目录深度、总文件数、字节数，并跳过二进制和构建产物。**文件树是可读清单，不是可写清单。**

### 关卡的“代码文件”菜单（2026-11-24 核对当前前端）

在题目公开网页加载的关卡组件中，代码编辑器使用与用户提供的 DOM 一致的图标和样式类名。关卡详情返回后，当顶层 `st === 0` 且 `challenge.path` 有值时，页面执行 `challenge.path.split('；').filter(Boolean)`，将数组赋给 `codeRepData.paths`，取第一项为默认文件。下拉按钮把这个数组中的路径逐项显示，点选时切换当前路径。此处使用全角分号 U+FF1B，路径末尾的分隔符不会产生额外文件。菜单生成过程不依赖展开工程目录。[当前关卡组件](https://www-cdn.educoder.net/p__tasks__index.b3a68008.async.js)

此前 JavaBean 第三关实测得到 `challenge.path = "JavaWeb/WebContent/book.jsp；"`。按上述初始化规则，预期菜单只有 `JavaWeb/WebContent/book.jsp`。上次同时修改的两个结果页超出了这个推定范围。三关评测通过只记录作业结果。第一、二关的实际菜单、作业列表第二页不同题型的样本，以及同一作业各关是否使用相同仓库实例，仍待在登录后的页面核对。

头歌手册的“评测设置”说明出题人可以为每关设置多个学员任务文件。第 6.2.4 节另行说明出题人可以控制版本库目录的可见性。因此 agent 应按关卡重新读取文件列表，独立记录工程目录是否可见。[头歌平台使用指南，印刷页 57、75](https://bdgit.educoder.net/EduCoderTeacher0028/pke-doc/raw/commit/7518966eb1be0a9ae9a5191aa2dffb1477d33a2a/pictures/EduCoder%E5%B9%B3%E5%8F%B0%EF%BC%88%E5%AD%A6%E7%94%9F%EF%BC%89%E4%BD%BF%E7%94%A8%E6%89%8B%E5%86%8Cv5.0.0_20200924.pdf)

平台侧写权限不能代替关卡下拉列表：为核验权限，曾对 `src/test/HelloWorldTest1.java` 加入一个空行并保存，`update_file.json` 返回 HTTP 200；随后立即撤销并保存恢复。该测试文件在 API 层可写，却不代表它列在当前小题的可编辑文件中。自动解题应先读取关卡级下拉列表，并把它固定为本关的写入范围；如某项与测试文件或构建产物冲突，应停止自动写入并核查。

## 已发现的补充调查面

这些是**页面路由或功能**，不是已确认的 JSON 端点：

- `program_homework` 和 `shixun_homework` 各有列表、作业详情及进度视图；后续需要追踪它们实际对应的请求。
- 实训页有“自测运行”和正式“评测”，编程题有“调试代码”和“评测并提交”。架构上应把本地验证、平台调试、正式提交分为不同动作。
- 实训页支持代码文件、命令行、上一关/下一关和“恢复初始代码”“重置代码仓库”。恢复与重置会覆盖远端状态，默认禁用。
- 编程题有“操作记录/提交记录”和既有代码，支持增量续做与避免重复提交。

## 下一轮可复现的接口核验方法

1. 在专用 Edge 测试配置文件登录测试账号，在 DevTools Network 开启 Preserve log 和 Fetch/XHR 过滤。
2. 每个页面动作只触发一次，记录方法、路径、查询参数名、请求体字段名、响应字段名及状态码；对 Cookie、Authorization、签名、登录名、题目代码和附件内容脱敏。不要提交原始 HAR。
3. 从课程列表到作业详情，再到一条已完成的编程题及实训关卡，优先核验只读请求。用单独可丢弃的题目验证保存、评测与轮询，并记录提交前后结果 ID。
4. 为每条接口形成可运行契约样例：成功、未登录、签名错误、过期、无权限、空列表、评测中、评测失败。将 `头歌api.md` 的字段标为“已验证”或“待验证”。

官方页面：[头歌实践教学平台](https://www.educoder.net/)。文档中的 JSON 主机为 `https://data.educoder.net`；它的具体私有接口没有在本次调查中找到公开规范，因此应作为可能变化的内部接口管理。
